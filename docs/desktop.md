# Windows 桌面控制台

GS66 Control 使用单一浅色 WPF 窗口、系统标题栏、标准控件、图标工具栏和托盘。图标均有悬停提示与可访问名称；日常页只保留指标、图形、选择器和必要状态，来源与详细错误放在设置的诊断折叠区。没有第二套界面或主题适配分支。

## 使用与安装

完整发布包自包含，无需另装 .NET。解压后运行 `install-release.ps1`，文件先经过 SHA-256 校验，再复制到 `%LOCALAPPDATA%\GS66Control\app-<版本>` 的新目录，最后更新桌面 **GS66 Control** 快捷方式。旧窗口从托盘正常退出后再打开新版本。安装保留旧目录、设置和记录，不结束进程，不改变 MSI 服务，也不设置自启动；加 `-Launch` 可在安装后打开。

主窗口按普通用户运行。若系统拒绝普通权限的传感器访问，概览的盾牌图标可按次启用固定的只读采集进程，窗口保持普通权限；采集进程随窗口退出，不安装服务。曲线、性能和自动模式操作由固定 helper 按次请求 Windows 提权，不安装常驻管理员服务。应用前校验准确机型、BIOS/EC、原厂文件哈希、schema、状态及必要温度；状态未知、过期、外部变化或回读不一致会阻止确认成功。

## 概览与记录

概览按 2–30 秒间隔读取 CPU 使用率、内存、电量、CPU/GPU 温度和两个逻辑风扇通道的 RPM，保留最近 60 个 CPU 负载样本。系统指标来自 Windows 原生 API，温度来自核对过的 WMI 属性；缺失值显示“—”，不补零、不沿用旧读数。第三颗物理风扇尚未完成接口映射。来源见 [遥测说明](telemetry-provenance.md)。

录制图标开始／停止正常使用时的只读记录。记录保存实际方案、Windows 电源计划、温度与转速的平均值/P95、CPU 负载及供电证据；最多 1200 个样本，保留最近六条摘要，可导出 JSON/CSV。JSON 同时保留实际曲线及电源计划 GUID。选择两条记录后显示差值；至少需要 30 秒和十个完整样本，供电状态缺失／变化、断流或 CPU 平均负载相差超过十个百分点时不作直接比较。RPM 不等同于分贝，CPU 负载不等同于性能跑分，滑杆也不承诺已自动找到最优档。

## 方案与性能

方案包含 CPU/GPU 各六点速度、可选性能档及名称，支持保存、删除、JSON 导入/导出和托盘快捷应用。温度断点保持设备实际值，首点可为原厂 0；速度为原厂界面值 0–100，不宣称对应已标定的 RPM。曲线须单调，80°C 及以上的点保留至少 80；滑杆在设备曲线基础上生成安静／性能倾向的草稿，之后可逐点修改。读取设备曲线时若草稿已更改则保留草稿。

应用方案会先捕获新鲜完整基线，再启动独立 helper，记录每次变化的恢复日志；写入后由 helper 和窗口分别回读。生效期间 helper 监控温度、父进程心跳及外部变化。正常停止恢复原速度和性能档，保持原厂自动风扇模式；父进程失联、异常或温度触发时尝试自动模式回退并恢复。发现未知外部修改时不会覆盖。恢复失败／未确认保留诊断和恢复入口，允许受限接管或只读重新核对。系统、WMI provider 或恢复进程故障仍可能使软件恢复失败。

设备性能档显示省电／均衡／性能／极速，对应已审查的 C2/C1/C0/C4。方案可保持当前性能档或绑定其中一个。性能提升要求新鲜 CPU/GPU 温度；自定义风扇模式还核对曲线安全条件。原厂场景名与 Shift 值不是一一对应，档名不代表实测功耗或性能保证。设置页通过 Windows 原生 API 切换已有电源计划，不创建、删除或改写计划内容。

## 风扇与托盘

风扇页和托盘提供原厂自动模式；操作完成需有关联请求结果和独立回读，已是自动模式时不重复写入。托盘还可选择已保存方案、停止当前方案、显示、刷新和退出；应用托盘方案保留窗口中未保存的草稿。默认关闭窗口后留在托盘，显式退出会请求停止方案并让独立进程完成恢复。F5 刷新，Ctrl+S 保存，Ctrl+Alt+G 显示窗口；快捷键被占用时诊断会提示。

仅控制预检可调用固定路径、哈希核对过的 nvidia-smi 读取 RTX 2060 温度；普通周期监控不持续调用它唤醒独显。设置与记录分别位于 `%LOCALAPPDATA%\GS66Control\settings.json` 和 `tuning-records.json`，控制事务使用固定请求目录，不接受任意地址。
