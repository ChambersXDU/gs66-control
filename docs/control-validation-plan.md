# 控制功能的下一步验证

当前目标是原生 Windows 控制台，保存、应用和比较适合实际负载的风扇／性能方案，并继续研究原厂 UI 未暴露的能力。曲线与性能事务、独立恢复、滑杆及记录已经实现；2026-10-15 至 16 日已完成新版 Windows 验收、CPU/GPU 曲线及 C2/C0/C4 有界试验和原生电源计划切换恢复，已完成的试验不重复。实际结果见 [Windows 验证记录](windows-validation.md)，当前状态见 [开发矩阵](development-status.md)。下文保留原计划与历史，不能把旧待办当作新的试验授权。

下文的版本方法方案是历史记录，Get_WMI/Get_EC 的批准尝试和重试已结束，不能重复调用；Get_Data(0xD7) 的批准有界探测也返回 NotSupported，不重试。最新用户授权允许安全边界内的自主、可逆开发与短时验证，曲线／性能扩展按 AGENTS.md 最后一项例外执行；禁止条款仍有效。不要把历史“下一步批准”文字当成当前待提问事项。

## 拟执行的操作

通过 System.Management 在 `root\WMI` 取得原厂证据中的 `MSI_ACPI.InstanceName='ACPI\\PNP0C14\\0_0'` 对象，分别调用一次 Get_WMI、Get_EC；不提供输入参数，不调用任何 Set 方法。元数据已确认两个方法均无输入，输出为嵌入的 Data 对象。输出先作为未解码的证据保存在忽略目录，再按原厂 Parse_WMI_Info/Parse_EC_Info 的包结构核对 Flag、长度和版本字符串。失败就记录错误，不能切换到寄存器扫描、驱动、物理内存读取或 WMI repository 修复。

这一步只用于版本身份核对，不授予风扇/模式/充电写入权限，也不能证明任何未来写入安全。Get 前缀本身不是无副作用保证；当前依据是原厂版本初始化中的调用与解析代码，尚缺本机执行证据。确认后只允许这两个方法的有限验证，仍保持原厂服务与热保护。

## 首次控制写入前必须完成

绑定实际型号、BIOS 和 EC 固件；确认 MSI WMI 版本与 legacy/WMI2 分支；逐项核对目标实例、位掩码、参数单位和允许范围；建立独立恢复进程并验证进程退出/挂起时的恢复；建立可靠温度来源与原厂自动冷却 fallback。最后向用户展示具体控制项、将要写入的值与恢复值，单独取得首次写入批准。

曲线、Cooler Boost、充电上限、性能模式分别验证，不能从一项成功推断其他项可用。CPU/GPU 功耗限制与第三风扇仍没有已证明的独立控制接口，保持未知。任何写入都不应先停用 MSI 服务或关闭热保护。

## 2026-10-13 单次尝试与修复

用户已批准 Get_WMI/Get_EC 各一次版本验证。第一次脚本在完成调用尝试后的输出/清理阶段失败：PowerShell 的 WMI 对象适配器处理 Dispose 成员时触发不支持的属性访问，导致结果没有输出或落盘，因此没有可采信的协议/EC 版本结论。没有执行 Set/Init、寄存器扫描或其他回退。

已将调用与 WMI 对象生命周期处理移到直接 C# 代码，只向 PowerShell 返回字符串和 byte[] 等普通数据对象，避免适配器问题；方法名仍严格限制为 Get_WMI/Get_EC。修复版先只编译，未调用 Capture，也未进行第二轮方法调用。重试仍须用户确认，不能把原先“各一次”的批准扩展成无限重试。原始错误与脚本留在本地临时目录/忽略的 captures 中。

用户随后明确批准修复后各重试一次。直接 C# 版本已执行，两条结果均为 `ManagementException: Not supported`，没有 Bytes 返回包；结果成功保存到忽略目录。该结果不应升级为“本机所有 WMI 控制不支持”，也不能把 MSI_ACPI 类元数据视为协议 2 已验证。方法重试到此结束，后续继续检查既有原厂缓存/日志与 legacy 代码证据，不调用其他方法或写入接口。

## 后续只读属性找到 EC 标签

对 MSI_Software 现有 34 个 Active 实例的只读查询发现，索引 6–33 是 ASCII 字符串 `16V1EMS1.1090311202011:16:49`。项目按严格长度、同一实例基础、唯一连续索引/ordinal、版本格式和构建文本格式核对，报告版本 `16V1EMS1.109` 与原样构建文本。来源明确标为 MSI WMI 报告的 firmware tag，不将 SMBIOS 255/255、历史日志或 registry cache 当作版本。该身份结果尚不构成写入验证或第三方 `.118` 寄存器表的授权。

现有服务的物理读取候选已审查：本机 MSIAPService 的 IO 入口会调用 loadWinIO；服务正在运行不保证 DLL/driver 已初始化，错误路径还可能重载初始化。当前不执行服务管道读取，也不再需要通过它获取上述 WMI 标签。详见 [legacy 路径审查](legacy-version-read.md)。


## 2026-10-14 拟定的开机验收（历史计划）

先在新版本目录核对 source/release manifest，Windows 编译 CLI、桌面与 helper，运行当前 146 项单元测试。发布包运行 `verify-release.ps1`：全部文件校验、24 项曲线事务模拟、2 项跨进程模拟、25 项自动模式模拟、真实只读 UI smoke（滑杆／性能持久化、录制、记录不足比较拒绝、原生电源计划枚举、图标可访问性）以及 control-preview。结果与截图保存在新的忽略目录；任何必要身份、schema、hash、模式、温度不可用均先停止。绝不修改网络或原厂服务来绕过门槛。

只读通过后分别执行两个固定五秒试验，各有单次本地标记、独立 helper、恢复日志和独立最终回读。不要复用已消耗的旧 automatic trial。每项开始前重读完整基线和温度，要求 CPU <=80°C、GPU <=75°C；基线变化或未知就拒绝。静态映射和模拟成功不足以跳过这些条件。

- 性能：仅基线 Shift=C1 时，使用固定 performance-worker 请求 C2、省电、TrialSeconds=5；原值 C1 写入日志，五秒后按最新绑定与预期值恢复 C1。最终要求 OriginalRawByte=193、RequestedRawByte=194、FinalRawByte=193、RecoveryVerified=true、ReadBackVerified=true、IsSimulated=false，并再次直接读到 C1。基线不是 C1 时不猜另一个目标。降低和恢复都不能扩展为压力测试或 GPU 功率限制。
- 曲线：在温度断点与完整曲线仍一致时，仅将 CPU 第二个速度点增加 1，其他速度、温度和性能档保持基线。若超出 100、破坏单调或安全条件则拒绝。curve-worker 请求 IsTrial=true、TrialSeconds=5、ExpectedBaseline=新鲜完整基线、ParentPid/ParentStartUtc=当前验证父进程；父进程持续写两秒心跳，正常五秒后恢复原速度和原模式，异常则保持自动模式回退。最终要求速度序列等于基线、正常模式等于基线、RecoveryVerified=true、IsSimulated=false，并用新的直接读取确认。当前已知 CPU 第二速度 50，因此候选 51；实测基线优先，不能把历史数值当作新鲜证据。

每次只启动固定命令与 GUID 的 helper，按次 Windows 提权，不把只读后台任务脚本提升为通用管理员执行器。独立恢复进程不得被超时包装器杀掉；包装器超时表示结果未确认，应查日志及状态，而不是声称未发生写入。未知外部变化不覆盖，失败不自动重复试验。确认新写入和恢复后，再验证桌面点击／托盘方案操作与关闭回退。

最后在正常日常工作负载、同供电条件下录制至少两条足量方案；检查 CPU/GPU 温度、两路 RPM、CPU 负载与主窗口/helper 的 CPU、内存及空闲 GPU 状态。不开压力测试、不用转速编造分贝、不把 CPU 负载当作性能基准，也不在资源开销和新控制实机通过前停用 MSI 服务。
