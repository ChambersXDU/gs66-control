# GS66 个人调优

代码按个人工作机需求维护。打开“个人调优”可查看当前插电频率上限、生效 EPP、基础计划与滑块的各自值，以及微星保存模式。实时硬件档位需要启用硬件读数；未读取时明确显示未知。

## 日常切换

| 方案 | 插电频率上限 | EPP | 说明 |
| --- | --- | --- | --- |
| 轻声办公 | 2600 MHz | 75 | 新候选，待日常体验 |
| 安静均衡 | 2800 MHz | 65 | 比 3 GHz 少一些性能和发热余量 |
| 日常响应 | 3000 MHz | 65 | 当前恢复性能后使用过的参数 |

三档均保留高效睿频策略（3）和最大处理器状态 100%，只修改插电源。电池参数、风扇曲线和硬件 Shift 不随 CPU 快捷档切换。频率是 Windows 策略上限，不代表锁频或保证物理频率。

点击“应用插电方案”后会重新采集参数，比对计划与滑块上下文，写入前保存原值，同步基础计划和当前滑块 EPP，再独立回读。普通用户权限不足时，只为本次操作启动提升权限 helper。参数持久保存在 Windows，退出应用不会自动还原。其他应用仍可能覆盖它们。

“恢复上次设置”分别恢复原基础计划与原滑块值；如果计划、滑块身份或任何被核对的值已被其他程序修改，会拒绝覆盖，请刷新检查。每次成功操作都会生成新的恢复记录。设置目录为 `%LOCALAPPDATA%\GS66Control`；`cpu-policy-last-change.json` 是最近一次成功修改，`cpu-policy-pending.json` 仅在修改未完成或记录未收尾时保留，用于诊断，不能当成已应用证明。

高级参数应用后可以保存为自己的命名方案；以后从窗口或托盘切换。保存、删除方案只改变配置文件。托盘勾选根据读回参数判断，不能单凭上次点击的名称认定仍然生效。

## 风扇

“准备更轻声的曲线草稿”读取设备现有曲线，生成倾向 25 的草稿：低温速度目标下降约 5 个百分点，保留温度断点、单调性与高温最低速度。它不会直接应用，也不会连带选择硬件省电档。

在“方案”检查草稿后，仍通过现有固定绑定、温度检查、独立 guardian 和回读机制应用。停用、退出或温度保护触发时，按原有恢复机制处理。低温目标百分比变化不保证线性对应 RPM；本次没有直接压低实机风扇曲线，也没有做新的满载试验。

## 防止再掉到约 800 分

本机曾出现 Windows 参数保留、硬件却回到 C2 的情况。只关闭 Dragon Center 界面自启没有解决；其后台初始化会读取保存的场景。实机保存值 Mode=4（节能）对应性能设置 ECO；用户切换为 Mode=2（平衡）后实时恢复 C1。新页面只读检查这一保存值并提示冲突，不直接改微星私有设置或关闭其服务。

重启后核对：微星保存模式为平衡、实时硬件为 C1、Windows 参数与选用档一致。未获取硬件读数时不要把状态当作通过。保存场景改正后的新一次重启尚待实际确认。

## 已有短时对照

同一自动测量流程中，2.8 GHz／EPP 65 一次 CPU-Z 多核约 2040、峰值约 66°C／2727 RPM；3.0 GHz／EPP 65 一次约 2131、68°C／2840 RPM。后续恢复平衡场景回测约 2095。背景负载、热积累和测量方式会影响结果，用户手测不能直接与自动流程逐点比较。这些历史样本支持提供可回退的候选档，不证明全天噪声、分贝或最佳参数。

验证记录以本次构建的测试输出与独立只读 UI 验收为准；仓库不提交原始设备标识、WMI dump 或个人运行日志。

本次 196 项单元测试通过；CLI、桌面和 helper 在 Windows 构建通过。真实五页 UI 只读验收通过，原生 helper 的 3.0→2.8→3.0→2.8 GHz 及逐步独立回读通过，电池策略未改变，未新增风扇曲线写入或启动负载。最终选用“安静均衡”，上一次 3.0 GHz 记录可从窗口恢复。最终发布文件与本机验收输出保留在本地；离线包报告不会自动把重新生成的文件标记为硬件全项已验证。
